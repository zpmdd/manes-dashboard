## 2. PDF 规则与工程定义

| 依据 | 实现 |
| --- | --- |
| 第 1 页：半径、最少样本、核心/边界/噪声，示例 1 km / 3 | 参数可保存；邻域至少 3 辆不同车辆才为核心；噪声标签 `-1` |
| 第 2 页：同一时间段才可聚类 | 按 `GPS_DATE` 先分窗，再逐窗独立聚类；不按 `SI_DT` |
| 第 2–3 页：扩张、暂时噪声及流程图 | 仅核心点继续扩张；边界不扩张；暂时噪声可转为边界；噪声分支不终止遍历 |
| 第 3 页：经纬度用球面距离 | 输入 `[经度, 纬度]`，转弧度后 haversine，地球平均半径 6371.0088 km |
| 第 4 页：标签、成员、中心、最远覆盖距离、噪声集合 | 输出稳定成员键、球面均值中心、成员至中心最大距离与孤立集合 |
| 第 4–5 页：敏感性、业务取值与用途 | 参数及算法版本留档；示例值不视为已校准的生产阈值 |

PDF 示例未严格说明是否计自身，第 3 页写“小于 eps”，第 2 页 B 拉入 E 的叙述省略 B 是否核心。这里明确采用标准 DBSCAN 的 **计自身、距离 ≤ eps、仅核心扩张**，避免边界点无限串联。参照 [DBSCAN 标准参数定义](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.DBSCAN.html)和 [haversine 单位说明](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.pairwise.haversine_distances.html)。

簇标签 `0、1…` 只在当前窗内有效，不是跨窗永久热点 ID；界面「簇 1」对应标签 `0`。链式簇覆盖半径可能超过 `eps`。这是**固定时间窗内空间 DBSCAN**，不是 ST-DBSCAN。

## 4. 时间、去重与确定性

1. 无时区日期按北京时间 UTC+08:00 解释；显式 ISO 偏移按原偏移换算。严格校验真实日历日期，不依赖本机时区。
2. 固定窗为 `floor(epochMilliseconds / windowWidth)`，左闭右开。默认北京时间 `00:00–00:05`，恰好 `00:05` 进入下一窗。其他整数分钟仍以 Unix epoch 为对齐原点，不是滑动窗。
3. 以 `[号牌, 颜色]` 为车辆键，每窗取最新有效 GPS 点；较早记录及重复计入 `collapsedRows`。高频上报不能把一辆车变成多辆。
4. 最新同一时刻不同坐标，该车在此窗隔离到 `conflicts`；有更晚有效点则按更晚点。相同时间位置但其他字段不同，按字段序列稳定选择，不认定哪一条速度更真实。
5. 不同车辆完全重合可压缩为带权位置做空间查询，成员与车辆数全部保留；近似重合不改坐标、不四舍五入合并。
6. 按车辆键排序使结果可复现；同时被两个簇覆盖的非核心边界点归先遇到的簇。标签不作为跨窗同一热点身份。

固定窗会把边界前后的邻近观测分开。后续持续聚集需要另定义滑动窗或相邻窗关联，不能偷偷拼接当前统计。

## 5. 数据—算法—项目接线

```mermaid
flowchart LR
  A[原始 Excel] --> B[只读表头与类型识别]
  B --> C[校验 / 事件时间标准化]
  C --> R[无效行与原因]
  C --> D[SQLite 磁盘排序]
  D --> E[逐窗取每车最新点]
  E --> F[球面 DBSCAN]
  F --> G[窗口结果 / 批次清单]
  G --> H[小窗口 dashboard.json]
  H --> I[现有 JSON / HTTP 数据源]
  I --> J[Worker 按同算法及参数复核]
  J --> K[原地图 / 三卡 / 前后切换]
```

Excel 流式只读，归一数据进入临时 SQLite，磁盘索引按事件时间排序，内存只保留当前窗。不能按行政区先分开聚类，否则会破坏跨区邻域。

| 输出 | 契约 |
| --- | --- |
| `current.json` | 最后成功批次路径与 `runId`，整批成功才原子替换 |
| `manifest.json` | 源文件名/哈希、版本、参数、输入/隔离数、窗数、耗时、坐标声明 |
| `windows.ndjson` | 每窗文件索引及质量/聚集统计 |
| `window-<epoch>.json` | 15 字段 + 车辆键/源行/标签/点类型；簇成员/中心/半径、孤立集合及冲突 |
| `latest.json` | 最新窗完整结果 |
| `dashboard.json` | `{ "rows": [...] }` 最新窗点位，符合前端限制才生成 |
| `rejected.ndjson` | 源行号与隔离原因 |
| `observations.json` + `observations-N.json` | 使用 `--raw` 时输出完整原始行（含异常、重复、旧定位和源行号）的分片清单；用于浏览器调整时间窗 |

每条展示记录携带 `CLUSTER_OPTIONS`。画布没有显式算法配置时使用结果参数，避免离线调过参数而页面默默用默认值；地图属性中明确保存的参数优先。混合原始行与算法结果、或混合不同参数结果时整个源报错。

浏览器按收到的点位重算，不信任传入簇标签。**`dashboard.json` 只含最新窗已清洗点位**；批次总量、隔离和去重信息以 `manifest` 及完整窗文件为准。窗选择器只列出当前载入的窗，不代表全部历史。改变时间窗必须回原 Excel 重跑，界面会拒绝直接按新窗口重算已清洗结果，因为无法恢复被去重历史点；半径/最少车辆数可在现有窗内代表点上探索。

原始 Excel 追加 `--raw` 导出完整批次，放在可访问的同源静态目录或 GET 服务。数据源选择「车辆原始批次」，填写该批目录中的 `observations.json` 地址。页面按清单顺序读取所有分片后，交由 Worker 清洗、去重、分窗、聚类；读到部分批次不会发布结果。刷新画布只保存连接地址，不把原始记录塞进配置。上限 100,000 条、100 片，每片最多 1 MB / 5,000 条，导出器每片至多 1,000 条。超限、缺片、计数不一致、路径穿越、已处理记录或取消均拒绝。更大规模继续用离线逐窗结果，后续服务应按窗查询并在服务端调参。通用 JSON / CSV / HTTP 限制不变。

批次 ID 由源文件哈希、参数、表选择、是否导出原始批次及算法版本生成。相同输入重跑不覆盖完整目录；失败保留诊断 `failed.json`，不更换 `current.json`，不把部分簇伪装成完整结果。

## 6. 复用步骤与代码入口

运行目录 `dashboard`；Node.js 24，Python 3 需有 `openpyxl`，未添加前端依赖。

```sh
npm run cluster:vehicles -- \
  --input ../output/dbscan/source/demo.xlsx \
  --output ../output/dbscan \
  --python /Users/manes/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
```

本机可用 `fnm exec --using=v24.15.0 npm run cluster:vehicles -- ...`。其他机器填自己的 Python 路径或设置 `DAOYAN_PYTHON`。多表追加 `--sheet Sheet2`；表选择也参与批次身份，因此显式指定与自动识别会有不同批次 ID。

追加 `--options parameters.json` 可配置：

```json
{"epsKm":1,"minSamples":3,"windowMinutes":5,"coordinateSystem":"unknown"}
```

支持 `.xlsx`、原始记录数组 `.json`、`.csv`、`.ndjson` / `.jsonl`；旧 `.xls` 先另存 `.xlsx`。JSON 数组超过 50 MB 拒绝，使用流式输入；CSV 支持引号内换行，单条流式输入限制 1 MB。

大屏：齿轮「设置大屏」→「数据源」→选择原车辆源→「导入文件」选择本批 `dashboard.json`→核对列表路径 `rows`→「保存数据源」→「保存画布」。保留原源 ID，地图与三卡一起生效。页面现有文件入口是 JSON/CSV，不直接接收 Excel。已有 HTTP GET 能接返回此结构的接口，但接口服务需项目实际提供。

参数优先使用顶部「算法设置」：半径 0.001–200 km、最少车辆数 1–100,000（整数、含自身）、时间窗 1–1,440 分钟（整数）。取消保留当前参数，应用后保存画布参数并统一重算。原始批次可直接改窗，已清洗结果继续拒绝改窗。原地图属性入口保留，参数随画布与模板导入导出。时间窗代表参与空间计算的采样范围，不是持续停留或风险阈值。

## 7. 容量实测与扩展方式

内核采用三维单位球网格筛候选，再以 haversine 精确筛选，日期线与极区同样适用。不预存全部邻域矩阵，完全重合按权重压缩。**每窗最多 100,000 辆，候选距离检查最多 50,000,000 次**；超限明确终止，不随机抽样或截断。

Apple M2 Max / Node 24.15.0 的合成内核实测（`../output/dbscan/benchmark.json`）：

| 场景 | 点数 | 时间 | 结果 |
| --- | ---: | ---: | --- |
| 稀疏 | 10,000 | 50 ms | 完成，10,000 次检查 |
| 稀疏 | 100,000 | 589 ms | 完成，100,000 次检查 |
| 完全重合 | 100,000 | 17 ms | 完成，压缩为一个带权位置 |
| 密集且不重合 | 10,000 | 1,906 ms | 超 5 千万预算，明确失败 |

报告在版本标签定稿前运行，标记为 `daoyan-dbscan-1`，与最终 `1.0.0` 邻域内核相同。真实五行 Excel 一次完整批处理约 219 ms，含读取、中转、输出。合成内核时间**不代表大量 Excel 全链路吞吐或生产 SLA**；密集分布最坏仍为 O(n²)。

前端每源同时限制 **5,000 行及 1 MB**，带完整字段的记录可能先到字节上限；只有都满足才生成 `dashboard.json`。超限保留完整窗输出，并明确 `dashboardCompatible=false`，不截断成假完整窗口。

下一阶段先取得至少一天且覆盖密集场站/道路的真实 Excel，测采样间隔、重复率、窗内车辆数及峰值耗时。再根据瓶颈更换精确空间索引；若分区，应有 `eps` 邻域重叠并全局合并核心连通分量。简单每 N 行独立聚类再拼接会拆错簇，不可采用。

`verify` 包含应用测试、真实 Three/R3F 地图检查、双构建、Sites 打包及基线数据隔离；浏览器使用用户 Chrome。实际界面验收见 [验收记录](daoyan-dbscan-qa.md)。

## 2026-09-28 稀疏样本与展示边界

更新后的 10,000 条合成 Excel 覆盖 31 个省级区域，10 个五分钟窗中有 3 个无聚集窗，聚集车辆占比 0–2.72%，仅为演示设计。每窗 920 辆有效车，最新窗 3 簇 / 25 辆聚集 / 895 辆非聚集。独立场景预期验证每窗车辆、成员、角色、重复与异常隔离，不能把跨窗计数称为持续事件。

聚集占比图分母是当前窗去重并排除冲突后的有效车；柱形图展示有数据窗口，空缺不补零，点击切窗；排行按车辆数降序，参考地名来自簇成员 GPS 与离线边界。聚类地图以一次实例化绘制保留全部簇中心，最多 24 个簇文字标签，优先选中簇与大簇；不混显孤立车辆。切回窗内点位后，既有 64 个屏幕聚合标注保留全体车辆成员。地名只解析当前排行前 20 簇的代表车辆；切回原速度列表时恢复按需车辆解析。详细列表首屏限制 100 簇与 100 车，完整结果可导出。
