# 专业图表与商业编辑能力验收 · 2026-09-12

本轮在既定烟灰玻璃、香槟文字和共享三维地图上，增加专业图表、数据识别与磁吸多选布局。基于此前已提交的 `e5444a0` 继续迭代；以下为本地验证，未进行生产部署或现场设备验收。

## 实施依据

- [DataV 组件布局](https://www.alibabacloud.com/help/doc-detail/87484.html)：采用多选、六向对齐、水平/垂直等距等成熟编辑方式；本项目另提供同宽同高、画布参照与百分比精确尺寸。
- [Grafana Canvas](https://grafana.com/docs/grafana-cloud/learn-and-build/visualizations/panels-visualizations/visualizations/canvas/) 与[面板数据检查](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/panel-inspector/)：采用可见对齐参考线、数据预览和字段选择的操作方式。
- [Apache ECharts 按需导入](https://echarts.apache.org/handbook/en/basics/import/)及[渲染器选择](https://echarts.apache.org/handbook/en/best-practices/canvas-vs-svg/)：引入 Apache-2.0 的 ECharts 6.1.0，按需注册所用图表和组件；通常采用 SVG，实际绘制规模超过 1000 时选择 Canvas（多系列包含用于保留缺口的展开槽位）。

实现保留本项目的布局、色板和材质，未复制上述商业产品的商标、素材或产品界面。

## 性能与包体积

| 文件 | 原始 KB | gzip KB | 加载条件 |
|---|---:|---:|---|
| 主文件 | 1399.98 | 394.60 | 首屏 |
| ECharts 渲染组件 | 690.19 | 235.16 | 存在专业图表时 |
| 专业图数据与选项构建 | 11.11 | 4.75 | 专业图或编辑分析时 |
| 数据识别与建议 | 10.48 | 3.99 | 编辑数据/属性时 |
| 属性与模板面板 | 35.86 | 11.55 | 打开编辑器/模板时 |
| 数据源管理面板 | 19.94 | 7.28 | 打开数据源时 |

将编辑专用逻辑从运行时数据层拆出后，主包从本轮中间状态 gzip 400.19 KB 降到 394.60 KB，减少 5.59 KB。数据识别与运行时继续共用解析和 HTTP 读取实现，不维护第二份解析器；专业推荐使用实际图表构建器验证，不维护第二份类别/系列校验逻辑。

拖动以每帧一次 DOM 更新预览，松手仅提交一步历史；专业组件不依赖整个画布配置，纯位置变化不会重新生成数据。字段预览按数据与映射缓存，辅助线刷新不重复转换完整数据集。轮询仅改变加载/错误状态时，运行时映射、组件归一化和属性预览均复用已有数据，仍正常显示状态和延迟提示；新数据或映射变化才重算。地图仍按需绘制；常规全国帧为 347 次绘制、575,817 个提交三角面。业务洞察静置 208.78 秒，地图绘制帧保持 6；Chrome Performance 读数中脚本累计 300.90ms，布局累计 160.01ms，JS 已用堆从 40.75MB 到 40.96MB。页面每秒时钟更新仍保留；这只是本机短时样本，不代表长期内存或现场帧率承诺。

基础运行总览模板保存并重载后，Network 实际只记录一个应用脚本请求，未请求 ProfessionalChart、dataInference、EditorPanels 或 DataSourcePanel。

专业图缩放先提交延迟选项，再由尺寸变化消费待执行更新，真实 ECharts 回归确认从两次完整更新合并为一次；首次初始化不额外缩放，纯数据更新仍保留 280ms 动画。稀疏多系列以展开槽位判断渲染规模，例如 500 个真实点、500 个系列、100 个类目对应 50,000 槽，使用 Canvas，但数据点计数、系列和缺口不变。

跨 SVG/Canvas 重建只暂存图例选择和缩放边界，再合入第一次懒更新，不保留完整图表选项。真实替换实例验证恢复交互仍只触发一次完整更新；同类型数据更新与尺寸变化沿用已有 ECharts 合并行为。

字段分析改为按每行实际存在的自有属性归集，避免每个字段重新扫描全部行。相同 118,891 字节、5000 行稀疏嵌套 JSON，本机 Node 单次分析从 8141.55ms 降至 9.08ms；5000 个字段、空值数量及样本顺序不变，未采样或缩减输入。浏览器显示完整读取与识别 21–22ms；此处只衡量解析与字段分析，不等同于整个面板的交互耗时。

基础组件的数字格式器按 4 种精度与 2 种记数方式复用，最多 8 个实例。4000 次普通数值格式化的 Node 预热后 7 轮中位样本从 51.60ms 降至 1.52ms，输出逐个一致；本轮另将会舍入为 0 的非零数值改用科学记数法。轴刻度共用另外两个按需创建的格式器，保留 12 位有效数字，避免相邻小数刻度显示相同。这是格式化函数基准，不是整屏帧率。

数据源只在地址含 `{adcode}` 时把区域作为请求身份的一部分。四源场景（JSON、CSV、固定 HTTP、区域 HTTP）从全国切到北京，实际加载次数从 8 次降为 5 次，固定 GET 从 2 次降为 1 次；未变源保留请求、数据引用与刷新期限，源内容变化仍重新加载。没有新增缓存层。315 秒浏览器轮询验证基于同轮 `index-DbM40a5I.js` 构建；随后加入外部数据跨区域归一化复用，最终构建及完整回归基于上述最终主文件。

页面恢复时，仅 HTTP 或尚未成功的静态源重新读取。真实控制器搭配 5000 行 JSON、CSV 和一个 HTTP 源，20 次隐藏/恢复后，两种静态源的解析各由 21 次降为 1 次，总状态发布由 126 次降为 46 次，HTTP 仍读取 21 次。初次隐藏、空列表、隐藏期间改源、中断恢复和显式刷新均有回归；该数字是控制器验证，不宣称为浏览器前后台切换耗时。
